  What are Java Exceptions?
   - In Java, Exception is an unwanted or unexpected event, which occurs during the execution of a program, i.e. at run time, that disrupts the normal flow 
     of the program’s instructions. Exceptions can be caught and handled by the program.

  Errors:
   - Errors represent irrecoverable conditions such as Java virtual machine (JVM) running out of memory, memory leaks, stack overflow errors, library 
     incompatibility, infinite recursion, etc. Errors are usually beyond the control of the programmer, and we should not try to handle errors.

  Java try-catch block:
   * Java try block:
	- Java try block is used to enclose the code that might throw an exception. It must be used within the method.
	- If an exception occurs at the particular statement in the try block, the rest of the block code will not execute.
   * Java catch block:
	- Java catch block catches the exception from the try block. 
	- However, the good approach is to declare the generated type of exception.
	- The catch block must be used after the try block only. You can use multiple catch block with a single try block.
   *Java finally block:
	- Java finally block is a block used to maintain cleanable code and to deallocate resource such as closing the connection, etc.
	- Java finally block is always executed whether an exception is handled or not.

  Java Multi-catch block:
    - A try block can be followed by one or more catch blocks. Each catch block must contain a different exception handler. So, if you have to perform 
      different tasks at the occurrence of different exceptions, use java multi-catch block.
    - At a time only one exception occurs and at a time only one catch block is executed.
    - All catch blocks must be ordered from most specific to most general, i.e. Exception hierarchy.


  Java Exception Propagation:
    - An exception is first thrown from the top of the stack and if it is not caught, it drops down the call stack to the previous method. If not caught 
      there, the exception again drops down to the previous method, and so on until they are caught or until they reach the very bottom of the call stack. 
    - Note: By default Unchecked Exceptions are forwarded in calling chain (propagated).

  Java throw keyword:
    - The Java throw keyword is used to throw an exception explicitly.
    - We can throw either checked or unchecked exceptions in Java by throw keyword.
    - It is mainly used to throw a custom exception. We will discuss custom exceptions later in this section.
    - Used only for Throwable types(Exceptions and Error)

  Java throws keyword:
    - The Java throws keyword is used to declare an exception. It gives an information to the programmer that there may occur an exception.
    - Advantage of Java throws keyword
        Now Checked Exception can be propagated (forwarded in call stack).
	It provides information to the caller of the method about the exception.
    - Note: Checked Exceptions should be thrown compulsorily in throws.

  Important Methods in Java's Exception Class:
   1. getMessage():
	- Returns a detailed message about the exception. This message is often provided as a parameter when the exception is created.
	- Usage: Useful for understanding the specific reason for the exception.

   2. toString():
	- Returns a short description of the exception, which includes the class name and the detailed message.
	- Usage: Provides a concise string representation of the exception.

   3. printStackTrace():
	- Prints the exception and its backtrace (stack trace) to the standard error stream.
	- Usage: Helps in debugging by showing the sequence of method calls that led to the exception.

   4. getCause():
	- Returns the underlying cause of the exception if one was provided during the exception's construction, or null if no cause was provided.
	- Usage: Useful for exception chaining where one exception wraps another as its cause.

   5. initCause(Throwable cause):
	- Allows you to set the cause of the exception after the exception has been created.
	- Usage: Used in situations where the cause is not known at the time of creating the exception.

   6. getLocalizedMessage():
	- Returns a localized version of the message for the exception. By default it calls getMessage() but it can be overridden for different languages.
	- Usage: Useful for internationalization, when you want the error message to be localized for different languages.
  
  Re-throwing exception:
    - Re-throwing exceptions in Java refers to the practice of catching an exception and then throwing it again, either the same exception or a new one.

  Exception Chaining:
    - Exception chaining in Java is a technique used to associate one exception (cause) with another.
    - This is particularly useful when an exception occurs as a result of another exception, and you want to maintain the complete stack trace to provide 
      more context about the failure.

  What is a stack trace?
   - A stack trace is information consisting of names of classes and methods that were invoked right from the start of program execution to the point where 
     an exception occurred. This is useful to debug where exactly the exception occurred and due to what reasons.

    19. Java Exception Handling Best Practices?
	- Use Specific Exceptions for ease of debugging.
	- Throw Exceptions Early (Fail-Fast) in the program.
	- Catch Exceptions late in the program, let the caller handle the exception.
	- Use Java 7 ARM feature to make sure resources are closed or use finally block to close them properly.
	- Always log exception messages for debugging purposes.
	- Use multi-catch block for cleaner close.
	- Use custom exceptions to throw a single type of exception from your application API.
	- Follow naming convention, always end with Exception.
	- Exceptions are costly, so throw it only when it makes sense. Else you can catch them and provide a null or empty response.
    20. When to Use Try-With-Resources?
	- File Handling: When you're reading or writing files using classes like FileReader, BufferedReader, FileWriter, PrintWriter, etc.
	- Database Connections: When you're interacting with a database, using Connection, Statement, PreparedStatement, or ResultSet objects, etc., that 	  			need to be closed after use.
	- Network Resources: For network communication, using sockets (Socket, ServerSocket), input/output streams (InputStream, OutputStream), etc.
	- Streams and Readers: When you're working with I/O streams or readers, such as InputStream, OutputStream, Reader, Writer, etc., which require 				       explicit closing.
